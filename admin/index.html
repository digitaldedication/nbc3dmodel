Korte deel-links

Zonder publiceren zit het hele event (inclusief logo's en beelden) ín de link — die wordt dan duizenden tekens lang. Met een sleutel zet de beheeromgeving het event op de server en is de link kort: …/viewer/?e=TOKEN.

Twee soorten werken: een classic token (GitHub → Settings → Developer settings → Personal access tokens (classic)) met alleen het vinkje public_repo, of een fine-grained token met Contents: read & write. In een organisatie moet een eigenaar fine-grained tokens eerst toestaan/goedkeuren — lukt dat niet, gebruik dan het classic token. Zie docs/publiceren.md. De sleutel blijft in deze browser en komt nooit in een deel-link.

Geen GitHub-account nodig: iedereen die dit adres en wachtwoord heeft, kan korte links maken — en de link werkt meteen, zonder wachttijd. Opzetten van het adres (gratis, ±10 minuten): zie worker/README.md.

Geen sleutel en geen publiceer-adres? Gebruik dan per event de knop "Config downloaden + uploadpagina" — dan plaats je het bestand handmatig in configs/.

De preview rechts ververst automatisch na elke wijziging.

Voorbeelden laden…

Gepubliceerde voorbeeld-events uit configs/voorbeelden.json. Ze staan op de server en zijn dus in elke browser zichtbaar, ook zonder opgeslagen events. Bewerken laadt de gepubliceerde versie in het formulier en zet het event bij "Opgeslagen events" (zelfde token: opslaan + publiceren overschrijft het voorbeeld). Nieuw voorbeeld toevoegen: token + naam in configs/voorbeelden.json zetten.

Opgeslagen events

Nog geen events opgeslagen.

De korte link (?e=TOKEN) is het prettigst om te delen en blijft bij bewerken hetzelfde — daarvoor moet het event gepubliceerd zijn (bij publiceren via GitHub heeft de server daarna ongeveer een minuut nodig; via een eigen publiceer-adres werkt de link meteen). De lange link bevat het hele event en werkt zonder server, maar wordt met uploads duizenden tekens lang en kan bij kopiëren/plakken afgekapt raken. Events blijven in deze browser bewaard om ze later te bewerken.
